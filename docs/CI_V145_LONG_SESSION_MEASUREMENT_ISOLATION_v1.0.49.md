# v1.0.49 CI v1.0.45 장기 세션 측정 격리 핫픽스

## 증상

100-wave 브라우저 검증에서 목표 웨이브, 런타임 오류, 힙·텍스처·지오메트리 증가량과 WebGL 복구는 통과했지만 `frameP95`와 `longTasks`만 실패했다.

## 원인

기존 브라우저 하네스는 5웨이브마다 `gc()`를 직접 호출한 직후 10프레임만 측정했다. 강제 GC와 관찰자 전달 지연은 게임 플레이가 아니라 검증기가 만든 제어 작업이지만, 바로 뒤의 짧은 프레임 표본과 전역 long-task 누적값에 포함됐다.

10개 프레임 표본에서는 단일 GC 정지 프레임이 p95와 사실상 같은 위치를 차지한다. 100웨이브 동안 반복된 강제 GC는 long-task 증가량도 실제 플레이 부하보다 크게 만들 수 있다.

## 수정

- 강제 GC를 측정 구간 밖의 명시적 안정화 단계로 이동했다.
- GC 뒤 observer turn과 렌더 settle frame을 기다린다.
- 각 표본을 24프레임으로 확대하고 앞의 3프레임을 warm-up으로 제외한다.
- long-task 판정은 실제 측정 프레임 창에서 발생한 delta만 누적한다.
- 전체 브라우저 long-task 값은 `rawLongTasks`와 `rawLongTaskMs`로 보존해 진단 정보가 사라지지 않게 했다.
- 실패 시 실패 체크, 실제 metrics, thresholds, 최악의 프레임 표본 5개를 출력한다.
- 동일 패턴을 사용하던 v1.0.46 브라우저 릴리스 검증에도 같은 격리를 적용했다.
- v1.0.46 dist 검증을 현재 v1.0.49에서도 동작하는 `1.0.46+` 계약으로 수정했다.

## 변경하지 않은 기준

성능 기준은 완화하지 않았다.

- frame p95 한도: 34ms
- frame p95 추세: 10웨이브당 1.5ms 이하
- measured long-task 증가 한도: 12개
- 힙·텍스처·지오메트리 증가 및 추세 한도: 기존 값 유지

실제 측정 창에 50ms 이상의 프레임 정지가 반복되면 새 하네스에서도 실패한다.
