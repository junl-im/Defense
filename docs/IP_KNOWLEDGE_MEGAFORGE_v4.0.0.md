# 도깨비 디펜스 IP Knowledge Megaforge v4.0.0

## 목적

이 문서는 `Dokkaebi Luck Defense 3D`의 그래픽 제작을 실제 대량 생산 단계로 전환하기 위한 IP 지식 자산 기준선입니다. 단순한 아이디어 목록이 아니라 **자산 ID, 이름, 역할, 속성, 희귀도, 제작 프롬프트, 제외 프롬프트, 납품 경로, 11방향 규칙, 액션 타이밍, 소켓, 지면 앵커, GPU 예산, HUD 계약, 자동 검수 조건**을 함께 관리합니다.

## 그래픽 제작 우선순위

1. 전투 화면에서 가장 자주 보이는 영웅·수호대·몬스터·보스의 11방향 원화를 P0부터 교체합니다.
2. 근접 베기, 원거리 발사, 마법 시전, 포효, 타워 발사 액션을 서로 다른 준비·유효·회수 타이밍으로 제작합니다.
3. 수호성은 성장 5단계, 피격 4단계, 행동 3종의 조합을 사용합니다.
4. 월드 HP 바는 보호막, 브레이크, 기절, 중독, 화상, 빙결, 감전, 저주를 하나의 계층형 UI로 통합합니다.
5. 보스는 발 중심 접지, 머리·가슴·무기·발 피격점, 약점 하이라이트와 화면 점유율을 별도 보정합니다.
6. PC HUD와 모바일 HUD는 같은 셸을 축소하지 않고 서로 독립된 정보 구조로 유지합니다.
7. 실제 브라우저 10웨이브 캡처 검사와 최대 240분 성능 회귀 검사를 함께 통과해야 합니다.

- 좌우 반전 대체: 금지
- 각 방향: 독립 원본

- 권장 접지선: 셀 높이 92%

- 공격 프레임은 타격 방향과 투사체 진행 방향이 일치해야 함

## 제작 상태의 의미

이 업데이트는 대량 제작이 가능한 **지식·프롬프트·기술 계약**을 생성한 것입니다. 147,232개 레코드를 최종 원화 또는 최종 스프라이트로 자동 승인하지 않습니다.

- `knowledgeStatus: generated` — 제작 지식이 생성됨
- `artStatus: planned` — 최종 그래픽 제작이 예정됨
- `productionApproved: false` — 최종 승인 전
- 최종 승인 수: 0

이 구분은 시제품, 생성형 참고 이미지, 실제 납품 원화, 런타임 적용본을 혼동하지 않기 위한 영구 계약입니다.

## 생성과 검증

```bash
npm run generate:ip-mega:v4
npm run verify:ip-mega:v4
npm run verify:release:v111
npm run build:static
node scripts/verify-static-dist.mjs
```

`generate:ip-mega:v4`는 결정적 생성 방식입니다. 입력 규격이 같으면 동일한 JSON과 SHA-256을 생성하며, `--check` 모드에서 누락 또는 오래된 생성 파일을 실패로 처리합니다.

## 실제 아트 교체 단계

### 1단계 — P0 골든 세트

- 도깨비 전사, 궁수, 법사, 도사, 무당
- 대표 수호대 6종
- 일반 몬스터 8종
- 엘리트 3종
- 보스 3종
- 수호성 1세트
- 핵심 공격·스킬·피격 VFX
- PC/모바일 전투 HUD

### 2단계 — 11방향 확대

골든 세트가 방향·접지·피격점·가독성 검수를 통과한 뒤 P1 자산으로 확대합니다. 한 방향 샘플만 승인한 상태에서 일괄 생산하지 않습니다.

### 3단계 — 액션과 상태 조합

기본 이동 이후 공격, 스킬, 궁극기, 피격, 브레이크, 사망을 추가하고 수호성 상태와 월드 HP 상태를 연결합니다.

### 4단계 — 자동 회귀

모든 교체 묶음은 10웨이브 비주얼 검사와 장시간 성능 프로필을 통과해야 합니다. 실패 시 해당 자산 묶음만 롤백할 수 있도록 관계 그래프를 사용합니다.
