# 라니킹덤 v2.7 — 승인 왕실 배너 10번째 원본 실제 UI 적용

## 확정 기준
- 모든 기존 독립 이미지 PNG 원본 10종과 게임 내 대응 WebP 10종, 로고, 지형 아틀라스, GLTF 모델 4종 및 3D 왕국 자산을 그대로 보존한다.
- **SVG 금지**, 스프라이트 시트 절단 금지, 옛 이미지 불필요한 압축/색 보정/덮어쓰기 금지.
- 원본 이미지와 게임 런타임은 [Drive PNG+WebP 원본 ZIP](https://drive.google.com/file/d/17z3CxG084H009VspkNGYBaQMQDt9aXRf/view), [v2.5 원본 16개 Git blob 지문](../assets/rani/asset-integrity-lock-v25.json)으로 추적한다.
- 게임의 경제·건설·연구·외교·저장·영토·3D 지형을 수정하지 않고 승인된 이미지 **실제 사용자 화면 연결**에만 집중한다.

## 실제 코드 적용
1. 기존 독립 생성본 `assets/rani/ui/panels/rk_panel_royal_hud_v001.webp`은 **원본 512×254 해상도**이므로, 길고 얇은 상단 자원바에 억지로 늘리지 않는다.
2. `src/ui/ResourcePanel.js`의 **실제 왕국 정보창** `#hud-kingdom-panel`에 배너 이미지 + 원래 왕국 제목을 나란히 배치한다. PC의 기존 [왕국] 토글과 모바일의 기존 [왕국] 탭에서 나타난다.
3. `css/rani-royal-header-v27.css`를 별도 파일로 추가해 `aspect-ratio:512/254`, `object-fit:contain`으로 고정하며 1440·1024·390·320px 해상도별 크기를 최적화. 클릭을 가로채지 않고 반응형 왕국 타이틀이 잘리지 않도록 한다.
4. 기존 전역 `GameIcons.js` 이미지 실패 감지와 동일한 `rani-raster-image` / `rani-raster-fallback` 클래스를 재사용. 원본 WebP가 로드되지 않으면 왕국 기호를 대신 표시한다.
5. `assets/rani/manifest-v27.json`은 기존 v2.3 매니페스트를 **수정하지 않고 별도 버전**으로 생성한다. 기존 10개 WebP의 경로/바이트/원본 PNG 식별자를 모두 동일하게 두고, 왕실 배너의 상태만 `applied-royal-kingdom-info-header`로 갱신한다. 따라서 **이전 제작 원본 10/10종이 게임 UI에 사용**된다. 자원 5/주택/시장/항구 3/금장 버튼 1/왕실 배너 1.

## 자동 검증
- `scripts/check-royal-header-v27.mjs`: v2.3 원본 10개 1:1 보존, v2.7 10/10 적용 상태, 원본 종횡비, HTML 스타일 로딩 순서, 안전한 폴백, SVG/잘라붙이기 금지를 검증한다.
- `scripts/qa_royal_header_v27.py`: **실제 PC 1440×900, 노트북 1024×768, 모바일 390×844, 소형 320×700** Chromium에서 원본 이미지 실로드 512×254, 화면 비율 유지, 버튼·메뉴 열기/닫기, 기존 자원 아이콘 5종·3D 마을·오류 없음 검증 및 스크린샷 저장.
- 이전 v0.1~v2.6 모든 경제/건설/지형/3D/자산 무결성/세이브/PC·모바일 검사 전체 유지. GitHub PR 두 검증 워크플로 성공 전 main 병합 금지, 병합 후 Pages + main QA 확인.

## 아직 완료되지 않은 그래픽
- 영향력·안정도·연구·건설·군사·지도·설정 등의 **새로운 개별 투명 PNG 원본**은 본 패치에서 새로 만든/적용한 것으로 간주하지 않는다. 조잡한 합성 시트 자르기나 시안 이미지에서 아이콘을 오려 쓰지 않는다. 새 독립 이미지는 원본 PNG 생성→독립 WebP 변환→Drive 원본 백업→매니페스트 추가→실제 UI 연동→QA 순서로 처리한다.
- 이전 원본 HUD 배너만 적용했으므로 전체 디자인이 사용자가 지정한 컨셉 이미지 수준에 도달했다는 뜻은 아니다.
- 실제 Android/iOS 물리 기기 GPU FPS와 발열 검증은 별도로 필요하다.
